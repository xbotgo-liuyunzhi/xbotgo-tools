# 精简 `xbotgo commit` 的终端输出

## 目标

执行 `xbotgo commit` 时，用户可以看到提交信息生成进度，并在成功后得到一行完整提交哈希和标题。两次生成都失败时，可以从终端看到每次失败的原因和 Codex 诊断。

## 方案选择

- **采用最终失败后一起显示。** 暂存每次 Codex 执行的诊断。第一次失败后只提示正在重试，重试成功后终端仍保持简洁。两次都失败时，可按顺序查看两次诊断。
- **每次失败立即显示。** 用户能更早看到原因，代价是第一次失败的日志会出现在最终提交成功的终端输出里。

## 输出行为

- 自动生成开始时，在标准错误流立即显示 `正在生成提交信息…`。第一次生成失败时，只显示 `正在重试生成提交信息…`。
- 将每次 Codex 执行的标准错误流写入本次命令的临时文件。两次都未取得有效提交信息时，按尝试顺序输出各自的失败原因和可用日志，提示用 `-m` 手动提交，并以失败状态退出。流程结束时清理临时文件。
- 普通提交、`-m` 提交和合并提交成功后，在标准输出流打印一行完整提交哈希和标题。Git 提交子进程的输出暂存到提交结束，提交失败时显示其中的 Git 或钩子诊断。
- 这套输出规则适用于创建本地提交的阶段。`-p` 触发的推送使用 Git 的终端输出和凭据交互。

## 验证

验证首次生成成功、重试成功和两次都失败的输出。覆盖 `-m` 提交、合并提交以及钩子拒绝提交，检查成功结果只有一行，失败诊断可见。运行仓库现有测试验证提交和推送行为。
